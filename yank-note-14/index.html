Yank Note 3.92.1 (opens new window) 发布了。这版本体升级了 Markdown 渲染、扩展 API、浮动编辑器和终端体验，也新增了“编辑装订线”和“审阅批注”两个扩展。

在我看来，它们都指向同一个问题：当 AI 参与写作后，人应该怎样更好地参与修改循环。

# AI 写作不是一次生成

只给 AI 一个题目，生成后不满意就换提示词重来，很难得到真正符合自己意图的文章。文章不只有内容，还包含作者的观点、语气、取舍和上下文，这些不能交给 AI 一次决定。

所以我更倾向于把 AI 写作看成一个循环：

  1. 人给目标和材料
  2. AI 生成草稿或修改建议
  3. 人阅读、批注、删改、补充判断
  4. AI 根据这些反馈继续修改
  5. 人再次审阅，直到文章变成自己的东西

上一篇文章介绍了怎样让 Agent 进入 Yank Note，这次 3.92.1 继续解决另一个问题：AI 进来以后，人怎样更好地控制这个循环。

# 审阅批注扩展

这次新增的“审阅批注”扩展，可以在预览中选择一段文字，然后添加批注。

以前让我指出某一段的问题，需要在提示词里重新描述位置和上下文，非常麻烦。审阅批注把反馈直接绑定到选中的文本，并以人和 AI 都容易读的 Markdown 结构保存在文档末尾。这样下一轮 Agent 读取文档时，就能同时看到原文和人的修改意见。

# 编辑装订线扩展

另一个新增扩展是“编辑装订线”。它会在 Monaco 编辑器装订线中显示新增、修改和删除的行。

AI 改文章时，最怕的是它悄悄改了很多你没注意到的地方。

写代码有 diff，写文章也需要 diff。特别是让 AI Agent 直接改 Markdown 文件时，人需要快速知道：

  1. 哪些段落被重写了
  2. 哪些句子只是润色
  3. 有没有偷偷删掉重要观点

编辑装订线不能替你判断好坏，但它能把“哪里变了”这个问题变得很显眼。这样人就可以把精力放到真正需要判断的地方。

这类功能在 AI 写作里会越来越重要。以前我们关注的是“如何让 AI 生成更多内容”，现在更应该关注“如何让人看得清 AI 做了什么”。

# Markdown 相关升级

这次还把 Markdown-it 升级到了 14.3.0，并增加了 CJK-friendly 强调解析，优化中文、日文文本的渲染。

AI 生成的 Markdown 常把 *、_ 紧贴中文或标点。Markdown 会根据标记两侧的空白和标点判断强调从哪里开始、在哪里结束，这套规则遇到通常不靠空格分词的中日韩文字时，结果有时不合直觉。CJK-friendly 解析就是针对这些情况做了适配。

另外新增了原始 HTML 容器，支持在 Markdown 内容中混合并直接渲染 HTML 区块。这对一些更复杂的文档和自定义内容会更方便。

# 其他修复

这次还修复了几个细节问题：

  1. 修复带语言标记的纯文本代码围栏重复转义
  2. 修复应用启动时无法正确恢复 HTML 及其他非 Markdown 文本文件内容
  3. 避免终端横向溢出导致输入法界面位置偏移
  4. Electron 升级到 41，并更新依赖和安全相关的间接依赖

其中终端 IME 位置偏移这个问题，对中文用户尤其明显。既然现在侧栏终端和 AI Agent 会越来越常用，终端里的输入体验也就变得更重要了。

# 最后

AI 可以起草、整理和润色，但文章最后留下什么，仍要由人决定。什么重要、什么该删、哪句话像自己，这些判断不能外包。

因此，我把 MCP、CLI、侧栏终端、审阅批注和编辑装订线看作一组协作工具：AI 可以直接推进文档，人也能看见改动、留下意见，再决定下一步。

我希望 Yank Note 能给你提供一个更适合人和 AI 一起写文章的工作台。
